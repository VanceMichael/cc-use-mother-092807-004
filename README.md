# 创新场景供需撮合与阶段成果验收

管理创新机会、能力、撮合、试点里程碑和案例发布。

## 参与方与事实

主要参与方包括场景运营团队、行业主管部门和需求单位、高校院所、技术企业、试点评审人员。领域资料记录以下已经确认的事实：

- 重庆征集场景机会、能力和案例三张清单
- 场景用于验证新技术、新产品、商业模式和制度政策
- 重庆将组织沙龙、揭榜挂帅和路演促进供需匹配
- 撮合只能使用供需双方互相授权披露的字段
- 揭榜时冻结当时的需求与能力版本，范围变化另立协商记录
- 试点容量签约时占用，失败/退出只释放尚未履行的部分
- 最终成效不由需求提出者单方确认，案例发布须双方授权

## 业务约束

- 机会与能力版本：递增发布，揭榜冻结版本号与内容指纹
- 授权披露：定向字段授权、可收回，未授权字段不进入匹配
- 试点资源：容量原子占用、不可重复占用、按未履行阶段释放
- 阶段验收：按顺序评价、结果封存、终验须需求方与评审共同确认
- 案例发布：双方分别授权后发布带冻结指纹的可复制案例

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/news_context_004.py` 负责读取和校验这些资料。

## 供需撮合后端

`src/scenario_matching/` 是完整的撮合后端领域层，采用事件溯源
（JSONL 事件流，状态全部由重放得到）：

| 模块 | 职责 |
| --- | --- |
| `domain.py` | 参与方、机会/能力版本、披露授权、适用范围、资源池、撮合单、冻结引用、协议、里程碑、协商记录、隔离材料、案例 |
| `store.py` | 事件存储：追加写 + fsync，重放时跳过崩溃造成的半截末尾事件 |
| `backend.py` | 命令入口与事件应用：撮合、揭榜冻结、材料隔离、评审、签约占容、协商、阶段评价、退出释放、案例发布、恢复待办、合作血缘 |

主流程：

```
发布机会版本 / 登记能力版本（敏感字段默认不披露）
        └─ 仅按双方互相授权字段撮合
              └─ 揭榜：冻结需求/能力版本号与内容指纹
                    ├─ 材料与冻结事实冲突 → 先隔离，运营复核
                    ├─ 评审通过 → 签约（原子占用试点容量，固化阶段指标）
                    │     ├─ 范围变化 → 协商记录，对方接受才生效
                    │     ├─ 里程碑按序评价，结果封存
                    │     ├─ 失败/退出：仅释放未履行容量，已完成阶段评价保留
                    │     └─ 全部通过（需求方+评审共同确认终验）
                    └─ 双方分别授权 → 发布可复制案例
```

重复申报（同一申报编号）直接返回既有撮合结果且不产生事件；
服务重启后可用 `recovery_worklist()` 取回待签协议、到期里程碑、
待补授权案例与待复核隔离材料；`trace_cooperation()` /
`explain_trace()` 按时间顺序还原一项合作从机会与能力走到可复制
案例的完整经过。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
