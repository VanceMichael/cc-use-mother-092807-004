# 创新场景供需撮合与阶段成果验收

管理创新机会、能力、撮合、试点里程碑和案例发布。

## 参与方与事实

主要参与方包括场景运营团队、行业主管部门和需求单位、高校院所、技术企业、试点评审人员。领域资料记录以下已经确认的事实：

- 重庆征集场景机会、能力和案例三张清单
- 场景用于验证新技术、新产品、商业模式和制度政策
- 重庆将组织沙龙、揭榜挂帅和路演促进供需匹配

## 业务约束

- 机会与能力版本
- 授权披露
- 试点资源
- 阶段验收
- 案例发布

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/news_context_004.py` 负责读取和校验这些资料。

## 供需撮合后端

`src/matching/` 把需求单位、机会版本、开放条件、能力主体、解决方案、保密范围、
试点资源、评审、协议、阶段指标和案例发布连成可追溯流程：

- **授权撮合**：字段级 `disclose_to`，匹配与申报只使用双方同意披露的字段。
- **版本冻结**：揭榜时冻结当时的需求与能力版本（指标、数据范围、开放条件），
  新版本不影响既有合作；范围变化只能走双方协商记录，协议哈希锁定冻结条款。
- **容量管理**：按“能力 + 冻结版本”预留试点容量，不能重复占用；失败或退出只
  释放尚未履行的资源，已通过阶段保留原评价。
- **独立验收**：阶段成效由独立评审人员确认，需求方不能自评；不通过可整改重报。
- **案例发布**：全部阶段通过后才能形成案例，须双方授权并通过独立复核才发布。
- **韧性与追溯**：重复申报幂等返回既有结果，冲突材料先隔离，`save`/`load`
  快照后可用 `resume_queue` 从待签协议、到期里程碑、案例复核断点继续；
  `explain_collaboration` 输出从机会与能力到可复制案例的完整时间线。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
