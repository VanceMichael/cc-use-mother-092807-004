# 领域边界

管理创新机会、能力、撮合、试点里程碑和案例发布。

现有领域资料围绕以下边界组织：

- 机会与能力版本
- 授权披露
- 试点资源
- 阶段验收
- 案例发布

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

## 后端实现（src/scenario_matching/）

后端采用事件溯源：命令先做规则校验，通过后追加一条不可变事件，
状态全部由事件重放得到，进程崩溃后重新加载事件流即可恢复。

### 状态流转

```
已撮合 SUGGESTED ──揭榜──▶ 已揭榜 CLAIMED（冻结需求/能力版本）
                              │
              提交材料（冲突先隔离）→ 评审
                              │
                     通过 ────┴──── 未通过 REJECTED
                              ▼
                          签约 SIGNED（占用试点容量）
                              │
               阶段里程碑按序评价（范围变化只追加协商记录）
                ┌─────────────┴──────────────┐
          全部阶段通过                  失败/退出 TERMINATED
                ▼                    （仅释放未履行容量，
            已完成 COMPLETED            已完成阶段评价保留）
                ▼
     双方分别授权 ─▶ 已发布案例 PUBLISHED
```

### 关键业务规则

1. **授权披露匹配**：机会/能力各有字段；匹配引擎只使用需求方授权给
   能力主体、且能力主体也授权给需求方的字段。真实痛点等保密字段不授权
   就不会出现在撮合依据里；授权可以收回。
2. **揭榜冻结**：揭榜时记录需求版本号、能力版本号及两者的内容指纹。
   此后任一方发布新版本都不影响已冻结合作；签约时的阶段指标只能取自
   冻结需求版本，改值或新增指标一律拒绝。
3. **范围变化走协商**：冻结后的变化（扩缩点、新增数据范围）只能形成
   协商记录，须对方接受才生效；冻结版本与指纹永不回改。
4. **能力多场景与适用范围**：一项能力可同时回应多个场景，但只能在
   登记的数据范围与试点规模内使用；范围不覆盖需求时拒绝签约。
5. **试点容量**：签约时原子占用，重复占用直接报错；容量不足时签约
   失败且不留中间占用。协商扩容即时校验余量。
6. **失败/退出释放**：按未履行里程碑等比折算释放（向上取整），
   已通过阶段占用的容量不退还，已封存的阶段评价保持原样，其余阶段
   标记为“已免除”。
7. **阶段与终验**：里程碑必须按顺序评价，已评价结果封存不可改；
   阶段评价必须有评审人员参与；最终成效不得由需求提出者单方确认，
   须需求方与评审共同确认。
8. **案例发布**：只有已完成终验的合作可进入发布；需求单位与能力
   主体分别授权，缺一不可；发布快照包含冻结版本指纹、阶段结果与
   协商记录，作为可复制案例的依据。
9. **重复申报**：同一申报编号重复提交时直接返回既有撮合结果，不
   产生新事件；同一编号试图换绑另一对供需会被拒绝。
10. **冲突隔离**：与冻结事实不一致的材料（改指标、声称其他版本）
    先进入隔离区并挂起原因，不得覆盖任何事实；运营复核给出
    “维持冻结版本/转范围协商”结论后才出隔离。
11. **恢复续办**：恢复后生成待办清单——待签协议、已到期里程碑、
    待补另一方授权的案例、待复核隔离材料；事件流末尾的半截写入
    被识别为崩溃残留并跳过，此前事实不受影响。
12. **可追溯**：每项合作可按事件顺序还原“机会/能力版本 → 撮合
    依据 → 揭榜冻结 → 评审 → 协议占用 → 协商 → 阶段评价 →
    案例发布”的完整经过（trace_cooperation / explain_trace）。
