# 领域边界

管理创新机会、能力、撮合、试点里程碑和案例发布。

现有领域资料围绕以下边界组织：

- 机会与能力版本
- 授权披露
- 试点资源
- 阶段验收
- 案例发布

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

# 后端不变量

`src/matching/` 实现上述边界的供需撮合后端，任何写操作都必须满足下列不变量，
`tests/test_matching_platform.py` 逐条覆盖。

## 机会与能力版本

- 机会和能力都以不可变版本序列组织；新版本开放后，未揭榜的旧开放版本标记为
  `superseded`，但已 `frozen` 的版本永久保留。
- 揭榜（`award`）当时同时冻结需求版本与能力版本：成效指标、数据范围、开放条件
  以冻结快照为准，事后发布新版本不改变既有合作。
- 一项能力可以同时回应多个场景；容量池按“能力 + 冻结版本”隔离统计。

## 授权披露

- 字段是披露的最小粒度，每个字段带 `disclose_to`；`"*"` 表示公开。
- 撮合与申报只能使用拥有方同意披露给对方的字段；行业主管部门未公开的真实痛点
  不参与匹配，能力方未授权的标签也无法形成匹配。

## 申报与揭榜

- 解决方案申报按业务内容生成指纹；重复申报抛出 `DuplicateSubmission` 并返回既有
  申报，不重复建单、不重复占用资源。
- 揭榜时按里程碑计划预留试点容量；`reserved + consumed` 不得超过该能力冻结版本
  声明的总规模，容量不足抛出 `CapacityError`，杜绝重复占用。
- 协议内容哈希覆盖冻结版本、数据范围、成效指标与里程碑；与冻结内容不一致的协议
  不能签署，防止需求方事后悄悄更换指标。

## 范围变化（协商记录）

- 冻结快照不被原地修改；任何范围、到期日、资源数量变化都生成一条协商记录，
  保留变更前值与变更后值。
- 协商需双方达成一致（提出方提议即视为本方同意，对方响应后定论）；被拒绝则
  条款保持不变。
- 已履行（`consumed`）的资源不可再协商；变更前值与当前状态不符时必须重新协商。

## 试点资源

- 资源三态：`reserved`（预留占用）→ `consumed`（阶段验收通过后履行，永不释放），
  或 `reserved` → `released`（失败/退出时释放）。
- 终止合作只释放尚未履行的预留资源；已完成阶段的评价与已消耗资源原样保留。

## 阶段验收

- 阶段上报必须逐项对应当初冻结的阶段指标。
- 验收只能由独立评审人员（`reviewer`）作出；需求提出者和能力方都不能评价自己的
  合作，需求方不能单独确认最终成效。
- 评审不通过可整改重报；一旦通过即定稿，不可更改。全部阶段通过后合作才完成。

## 案例发布

- 只有全部阶段验收通过的合作能形成案例。
- 发布必须同时取得需求方与能力方的授权，缺一不能送复核；单方授权不足。
- 案例还要通过独立评审复核；复核不通过不得发布。

## 冲突隔离与服务恢复

- 并发冲突的材料先进隔离区（`quarantine_material`），不覆盖既有事实，处理结论
  记录在隔离条目上。
- 平台状态可整体快照（`save`/`load`）；`resume_queue` 在服务恢复后列出待签协议、
  到期里程碑、待复核案例与未处理隔离材料，流程从断点继续。

## 全链路追溯

- `explain_collaboration` 按时间线还原一项合作：撮合依据（含双方可见字段）→
  揭榜冻结的机会/能力版本 → 协议 → 协商记录 → 各阶段上报与独立评审（含资源
  履行状态）→ 终止释放或案例授权、复核与发布，使参与者能够解释合作如何从
  机会与能力走到可复制案例。
